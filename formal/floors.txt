\* WHAT EACH CONFIGURATION MUST PRODUCE, so that a run nobody watched cannot
\* pass by getting SMALLER. `Seams.cfg` once came back GREEN over ONE distinct
\* state -- every invariant holding vacuously, because a precedence slip had
\* turned an assignment into a guard that disabled both SELECT actions (E164).
\* A one-state GREEN is indistinguishable from a real one in the log, and the
\* runner's `VACUOUS` heuristic only sees the collapse all the way to nothing.
\*
\* The floor is an ORDER OF MAGNITUDE, not a pin. It is set near a third of the
\* measured count so that ordinary fidelity churn does not trip it -- this model
\* has legitimately shrunk 23% in one round -- while a collapse cannot pass. A
\* GREEN below its floor is reported as FLOOR and exits non-zero; re-measure and
\* move the number deliberately, the way the gate's other ratchets move.
\*
\* The VERDICT column is the second half, and it catches the other silent pass:
\* a mutant that stops firing. `BugSetPinKeepsPpuat` explored 40 459 667 states
\* without a counterexample after a fix made its defect unreachable (E171) --
\* far above any floor, and only visible because somebody read the matrix.
\*
\* And a RED verdict alone is not the third half. A mutant can go red for a
\* defect it does not model -- 2 of 24 co-refutation patches in this tree scored
\* a kill that way -- so a RED row may name the invariant it must break, and the
\* runner compares it. Measured on this file: flipping the alwaysUv mutant to the
\* INVERSE defect kept `TraceSecurityBadAlwaysUvArm.cfg` red, on a different
\* boundary and a different direction, and nothing noticed until the name was
\* compared. The `Mut_*`/`Solo_*` families already name theirs through
\* `gen-configs.sh`'s INVARIANTS block, so the column is for the rows that do not.
\*
\* The depths in the comments below are the WORKERS=1 reading, and they are the
\* one number here that nothing compares. TLC reports the deepest BFS level its
\* workers OPENED, which overshoots the diameter by one when a worker starts the
\* next level early -- `Store.cfg` is 6 at one worker over six runs, 6 or 7 at the
\* default two over thirteen, 7 at four and at eight. A ratchet on it would be red
\* or green by scheduler, so there is none: re-measure by hand with
\* `WORKERS=1 ./run-tlc.sh <cfg>`.
\*

\* First match wins, so an exact name may precede its class glob.

\* THE WRITE/RE-ARM ORDER, both arms. Every configuration above collapses the
\* record write and the re-arm into ONE step, so a power cut between them has
\* nowhere to sit and the order they ship in is unfalsifiable; these two split
\* the pair around an in-flight flag and differ in nothing else. The RED row is
\* the order the tree shipped until the re-arm was moved ahead of the write --

\* the order the tree ships now.

\* runner would derive the same name from its INVARIANTS block; what the column
